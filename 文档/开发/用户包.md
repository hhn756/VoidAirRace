# 用户包

“用户包”（**User Package**）是用户向插件添加自定义内容的唯一载体。一个用户包对应一个 `.zip` 文件，包的全部内容都在其中；开发期也可以用展开的目录形式（见[加载与校验](#加载与校验)）

定位：内容层。包里放的是“内容”（竞技场、地图等元素及其数据与逻辑），不是“能力”——能扩展系统的接口（比赛组件等）仍然只有插件本身的 Java 代码可以实现，用户包通过脚本注册元素，不产生新的扩展点

## 文件结构

```
/pack.varmeta   # 包的引导信息，仅含执行前必需字段
/scripts/       # 全部 Lua 脚本，包的所有逻辑
/assets/        # 可选。包自用的文件，格式与内部结构不限（见下）
/resourcepack/  # 未来：附带的资源包（mc原版概念）
```

`/assets/` 是包存放自用文件的地方，内部结构不限。该目录是可选的，一个纯逻辑的合法包可以没有它

包不支持附带数据包。数据包由服务器统一管理，内容有变动就意味着全服重载，与运行期可装卸的包不是同一层的粒度；包里需要静态内容时，用 `/assets/` 交给脚本处理，或用竞技场模板预摆物品。由此，包能定义玩法逻辑（地图、规则、脚本、模板、资源），不能定义游戏内容（战利品表、配方、数据包侧标签、进度、结构生成等）。插件自身携带的数据包不受此限，包里只能引用

发布的 zip 允许两种等价布局：包内容直接位于压缩包根目录；或全部内容位于压缩包内唯一的顶层目录中（即“先打包目录再压缩”的产物）。两种布局视为同一个包

## 引导与元数据：settings.gradle 模式

元数据分两半，划分标准是**执行脚本前是否必需**

`pack.varmeta` 只保留引导字段，扁平、封闭、几乎不再增长：

```yaml
id: mypackage        # 包标识，也是命名空间
version: 1           # 包自身声明的的逻辑版本，只能是正整数，用于判断新旧（值越大越新）
entry: main.lua      # 相对`包根/scripts/`
api: [1, 5]          # 对插件 API 版本的约束，第1项为最小版本号；第2项为最大版本号
dependencies: [a, b] # 可选。依赖的包 Id 列表
```

其余元数据（包名称、作者、描述，以及元素声明本身）全部由脚本定义，如同 gradle 构建脚本里的 `project` 对象。要执行脚本就必须先知道入口，要防撞车就必须先知道 id，要拒绝不兼容包就必须先知道 API 约束——这三样不能是自举的，所以留在 varmeta

依赖同理：必须先于脚本执行，已知才能排定包的加载顺序。包按依赖关系拓扑排序加载，依赖关系存在循环时环内的包全部拒绝；声明的每个依赖包都必须加载成功，缺依赖或依赖包未被启用的包随之一并失败

代价是完整元数据需要跑一次脚本才能获得，管理员查看包列表时读取加载后的内存缓存即可

## 插件 API 版本

插件 API 版本是一个整数，唯一标识暴露给包脚本的**能力集**：函数集合、各函数行为、描述符契约等的整体。包通过 `api: [min, max]` 声明自己支持的能力集区间，插件当前版本落区间外时在加载期直接拒绝（而非运行期报 nil 错误）

### 更新规则

**包可见的 API 面发生变化就 +1**——新增算变化，破坏也算变化；纯内部改动不算；拿不准就更新：

| 改动                                         | 是否更新   | 理由                                                                 |
|----------------------------------------------|------------|----------------------------------------------------------------------|
| 新增 API 函数 / 新开放注册类别               | 是         | 能力集变大；想让包声明“我需要这功能”，得有新版本号可填 `min`         |
| 破坏性变更（收紧校验、改返回值协议、删函数） | 是         | 能力集变化，旧包的 `max` 依赖它拦截                                  |
| 可观察行为变化（如读取大小上限调整）         | 是（顺手） | 偏向多更新：多更的代价只是个别包改一行 `max`，漏更的代价是运行期崩溃 |
| 插件内部重构、包不可见的修复                 | 否         | 包作者视角什么都没变                                                 |

**最小变更单位为一次提交**：版本号描述的是对外界（包作者）可见的能力集，外界收不到的中间状态没有版本号可言——开发过程中的多次调整合并为一次递增，版本记录只写净效果，不留中间态。因此版本号在提交前按本次提交对外的净变化定一次即可

两条配套习惯：

- 每次更新版本号，在版本号定义处留一行变更说明（如 `7: 新增 read_config；8: register 拒绝未知字段`）——包作者设置 `min` 时需要查“哪个版本加的这功能”，这张表就是答案
- “仅破坏时更新”漏掉的场景从来不是破坏，而是**新增**：只按破坏更新的话，带新功能的版本与不带的版本共用同一个号，包只能写 `[5, ∞)`，加载到旧插件上就在运行期炸出 `attempt to call nil`

版本号上界为 32 位整数上限，按“面向变化即更新”的节奏用不完，无需分段规则（不搞 major/minor）

## 资产文件

`/assets/` 里就是普通的文件。脚本按包内相对路径读取所需文件并自行解释内容，插件不预设也不解析文件格式

文件的格式与粒度都不限定，例如：

- `.nbt` mc方块结构
- `.txt` 纯文本
- `.yml` 内部配置（可由管理员修改的配置不在此列，由插件本身将在未来添加的功能储存）
- 一个目录，内含上述任意文件，由读取它的脚本自行约定组织方式

护栏仍然成立：文件里放的是静态数据，一旦某个东西需要条件分支或计算，它就属于逻辑，应该进 `scripts/`，而不是往文件里塞求值语法

## 脚本

`/scripts/` 下全部为 Lua，由插件内置的 Lua 运行时执行，`entry` 指向的脚本是包逻辑的唯一入口。注册行为统一且唯一地发生在脚本执行时，与注册表设计自洽（注册项无类型约束，任意对象可注册）

脚本路径：包内访问自身脚本时，所有路径相对自己的 `/scripts/` 目录；外部（其他包）访问某包的脚本时，只需在路径前额外包含包id（如 `mypackage:utils/math.lua`）

两条规矩：

- Lua 运行时本身不是沙箱，暴露给 Lua 的 API 面由 Java 侧白名单式给出，这决定安全边界
- 各包的脚本环境互相隔离，A 包的 Lua 状态不能触到 B 包的对象

## 脚本 API：注册

插件向包环境（`_G`）装入一组全局表，`register` 表的类别注册函数用于向插件注册游戏元素：`register.<类别>(descriptor)`，`descriptor` 为描述符（表）。注册只发生在脚本执行时；任何校验失败都会抛出 Lua 错误，导致入口脚本执行失败、**整个包加载失败**——不存在“部分注册成功”的中间态

当前版本开放 `map`（游戏地图）、`rule`（比赛规则）与 `tag`（标签）三个类别函数；道具等类别将随对应功能开放

### 标签描述符

```lua
register.tag({
    id = "my_tag",               -- 必填。仅写键名，插件自动加包 Id 前缀，最终标签 Id 为 "包id:my_tag"
    names = { "我的标签" },       -- 可选。展示名称
    description = { "……" },      -- 可选。展示描述
    authors = { "……" },          -- 可选。作者
    display_version = "v1",      -- 可选。展示版本（任意字符串，区别于逻辑版本）
    version = 1,                 -- 可选。逻辑版本，正整数，值越大越新
})
```

标签是纯数据的注册项，没有回调与实例化语义，作为游戏元素的通用特性标注，供后续的选择器类功能消费。字段校验规则与规则描述符的可选元数据字段一致（id 必填，匹配 `[a-z0-9_-]+`，重复注册失败）

### 比赛规则描述符

```lua
register.rule({
    id = "my_rule",              -- 必填。仅写键名，插件自动加包 Id 前缀，最终规则 Id 为 "包id:my_rule"
    names = { "我的规则" },       -- 可选。展示名称
    description = { "……" },      -- 可选。展示描述
    authors = { "……" },          -- 可选。作者
    display_version = "v1",      -- 可选。展示版本（任意字符串，区别于逻辑版本）
    version = 1,                 -- 可选。逻辑版本，正整数，值越大越新
    tags = { "my_tag" },         -- 可选。标签引用，语义见下
    on_enable = function(match)  -- 可选。规则在比赛中启用时调用
        return true              -- 返回值协议见下
    end,
    on_disable = function(match) end,  -- 可选。规则停用时调用
    tick = function(match) end,        -- 可选。每刻回调
})
```

字段校验规则：

| 字段                                | 约束                                                                              |
|-------------------------------------|-----------------------------------------------------------------------------------|
| `id`                                | 必填，字符串，匹配 `[a-z0-9_-]+`；加包前缀后作为规则 Id，与其他规则重复时注册失败 |
| `names` / `description` / `authors` | 数组表（键 1..n 连续），每项为字符串或文本组件描述符，可省略                       |
| `tags`                              | 标签名数组表（键 1..n 连续），可省略；引用语义见下                                |
| `display_version`                   | 字符串或文本组件描述符，可省略                                                     |
| `version`                           | 正整数，可省略                                                                    |
| `on_enable` / `on_disable` / `tick` | 函数，可省略；省略时对应生命周期走默认行为                                        |

`tags` 的引用语义：

- 裸键（不含 `:`）自动加本包 Id 前缀，等价于引用自己的标签
- 跨命名空间引用须写全名（如 `"void_air_race:official_tag"`）。允许引用自身、插件（`void_air_race` 命名空间）以及依赖链上游包的标签，越出范围的引用注册失败
- 引用的标签必须已注册：同一脚本内 `register.tag` 必须先于引用它的 `register.rule`，引用未注册的标签同样导致整包加载失败

`on_enable` 的返回值协议为 `ok[, err]`：

- `ok` 为 `true`：启用成功
- `ok` 为 `false`：启用失败，`err`（字符串，可省略）作为失败原因
- 返回格式不对（首个返回值不是布尔值）：视为启用失败

地图与规则的回调收到的 `match` 参数是本场比赛的句柄表，内容见[比赛句柄](#脚本-apI比赛句柄)

> 设计说明：
> `id` 只写键名、由插件自动加包前缀，是为了把包能触及的 Id 空间限定在自己的命名空间内——包脚本无需（也不能）手写前缀，天然杜绝跨包冒用他人命名空间。注册失败导致整包失败与既有包加载语义一致：包要么完整可用，要么完全不加载

## 脚本 API：全局操作

插件向包环境（`_G`）装入的全局表：`voidairrace` 仅承载插件元数据（目前只有 `api_version`），函数一律按类别入独立全局表——「不随意操作」的边界即这套全局表的整体。资源所有权挂在包的生死上：包卸载（或加载失败）时，本包借走未归还的竞技场由引擎统一归还，事件订阅自动清空

```lua
voidairrace.api_version     -- 插件 API 版本号（数字，voidairrace 表唯一的成员）

server.broadcast(message)   -- 向全服广播一条文本消息（字符串或文本组件描述符表）
server.online_players()     -- 返回当前全部在线玩家的 UUID 字符串数组（键 1..n 连续）
player.position(uuid)       -- 返回玩家所在世界坐标表 {x=, y=, z=}；玩家不在线即抛错
player.team_of(uuid)        -- 返回玩家所属队伍的数字 Id（1 起始，与内置队伍顺序一致）；未入队返回 nil
player.online(uuid)         -- 返回布尔值：玩家是否在线（离线不抛错，UUID 非法才抛错）
player.play_state(uuid)     -- 返回玩家在 play 状态体系下的状态键名（"free" / "playing"）；未初始化返回 nil
arena.borrow()              -- 借用一个竞技场，返回竞技场句柄表；无空闲即抛错（消息含各占用者）
event.on(name, fn)          -- 订阅引擎事件；未知事件名即抛错。无返回值
event.off(fn)               -- 退订：移除该函数在所有事件上的全部登记；未登记时静默无操作
```

> 这些全局名（`player` / `event` / `arena` / `server` / `register` / `resource`）由插件占用；包脚本若定义同名全局会覆盖 API，加载期用 `local` 承载自己的同名数据即可避免

> 文本组件：`server.broadcast` 与注册展示字段（`names` / `description` / `authors` / `display_version` / `links`）接受字符串（= 纯文本快捷路径）或文本组件描述符表——颜色、样式、点击/悬停事件、translatable 等完整规格见 [LuaAPI.md 的「文本组件描述符」节](../通用/LuaAPI.md)

玩家的 Lua 表示统一为 UUID 字符串，队伍为数字 Id——二者都是值而不是句柄。坐标与朝向同样走值语义：坐标为命名键表 `{x=, y=, z=}`，方块坐标按向下取整落格；朝向为 `{yaw=, pitch=}`，单位为度

### 事件列表

`event.on` 的事件名是固定集合（订阅点校验，未知名字报错）；回调在主线程执行，事件字段作为位置参数传入，每次调用单独计算指令预算（单次最多执行的 tick 数）：

| 事件名                  | 回调签名                             | 触发时机                                        |
|-------------------------|--------------------------------------|-------------------------------------------------|
| `"player_join_match"`   | `function(uuid)`                     | 玩家加入比赛（开局不会为初始参赛者补发）        |
| `"player_leave_match"`  | `function(uuid)`                     | 玩家退出比赛（淘汰/离场）                       |
| `"match_start"`         | `function()`                         | 比赛开始                                        |
| `"match_state_changed"` | `function(state_name)`               | 比赛状态变化（不含开始与结束）                  |
| `"match_over"`          | `function()`                         | 比赛结束                                        |
| `"player_join"`         | `function(uuid)`                     | 玩家加入服务器                                  |
| `"player_quit"`         | `function(uuid)`                     | 玩家离开服务器                                  |
| `"player_death"`        | `function(uuid, killer_uuid_or_nil)` | 玩家死亡；击杀者是玩家时给出其 UUID，否则 `nil` |
| `"player_respawn"`      | `function(uuid)`                     | 玩家重生                                        |
| `"player_move"`         | `function(uuid, pos)`                | 玩家所在方块变化；同方块内走动与转头不触发      |

回调抛错时记日志并广播原因，但不自动终止比赛——全局回调不承担比赛推进职责。参数只含值（UUID 字符串、状态名、坐标表），不暴露事件对象或比赛对象，也不支持取消与改写

`player_move` 是唯一按位置触发的事件，桥接层做了两道过滤：同方块内的位移与转头不派发，同一玩家两次派发至少间隔 50ms（约每秒 20 次上限），坐标表为派发时玩家所在位置、不保证覆盖途经的每个方块；无人订阅时连方块比较都省掉。需要更细的位置仍可在 `tick` 回调里经 `player.position` 轮询

## 脚本 API：比赛句柄

地图与规则的回调收到的 `match` 参数是本场比赛的句柄表（**薄门面，每次回调现造**），只包含本质上需要比赛目标的操作：

```lua
match.state()               -- 返回比赛当前状态名（字符串）
match.contestants()         -- 返回初始参赛者 UUID 字符串数组（键 1..n 连续）
match.survivors()           -- 返回当前仍存活的参赛者 UUID 字符串数组（键 1..n 连续）
match.eliminated()          -- 返回已淘汰的参赛者 UUID 字符串数组（键 1..n 连续）
match.surviving_teams()     -- 返回仍有存活参赛者的队伍 Id 数组（1 起始）
match.join(uuid)            -- 使指定玩家加入本场比赛；已在本场幂等，已淘汰者不可重新加入，
                            -- 玩家须在线且处于空闲状态，否则抛 Lua 错误
match.leave(uuid)           -- 使指定玩家退出比赛（淘汰）；不在参赛集合中时静默无操作
match.stop()                -- 结束本场比赛（仅限协调器管理的当前比赛）；结束后句柄失效
match.remaining()           -- 返回剩余比赛时长（tick 数，非负整数）
match.set_remaining(n)      -- 设置剩余比赛时长（tick 数，非负整数）
match.time_flow()           -- 返回比赛时间是否随 tick 减少（布尔值）
match.set_time_flow(flag)   -- 设置比赛时间是否随 tick 减少（true 减少 / false 暂停）
match.enable_rule(spec)     -- 在比赛中启用规则；spec 为规则 Id（裸键 = 本包命名空间，或 "ns:key" 全名），
                            -- 允许的命名空间与标签引用一致（自身包、插件内置、已声明依赖）；
                            -- 命名空间越权、规则未注册或启用失败即抛 Lua 错误
match.widen(arena, tag)     -- 把竞技场句柄登记为本场比赛的区域（当前仅 "main"）；登记后归还职责
                            -- 移交比赛结束流程，手动归还通道关闭
```

比赛结束后（状态非进行中），句柄表上的任何函数调用都会抛 Lua 错误。唯一例外是地图 `on_over` 回调收到的句柄：此时比赛已进入结束流程，句柄只放行查询类函数（`state` / `contestants` / `survivors` / `eliminated` / `surviving_teams`），操作类函数一律抛错

### 竞技场句柄

`arena.borrow()` 返回的句柄表包装竞技场借用的完整协议（借用 → 加载模板 → 使用 → 归还）：

```lua
local arena = arena.borrow()
arena.load("assets/arena")          -- 将包内世界模板目录加载到竞技场；路径规则同 read_asset（包根相对，可跨包）
arena.teleport(uuid, pos[, rot])    -- 把玩家传送到竞技场世界内的指定坐标；rot 为可选朝向表
arena.clear_chest(pos)              -- 清空竞技场世界内指定方块的箱子；该坐标不是箱子时抛错
arena.release()                     -- 归还竞技场：世界卸载且不保存修改，场内玩家被传送回出生点
```

模板目录须为完整的世界数据（`level.dat`、`region/` 等），按包内目录形式存放。加载在借用期内可重复执行，每次都重新加载（不保存修改）

> 设计说明：
> 借用不绑比赛生命周期：竞技场持有时长 ≤ 所属包寿命，归还责任在脚本；包卸载时未归还的竞技场由引擎统一归还并记日志，脚本忘了归还也不会泄漏世界。已 `widen` 进某场比赛的竞技场禁止手动 `release`——归还职责已移交比赛结束流程（组件卸载时统一归还），防线在 ArenaManager 的登记状态上，不管归还请求来自哪条路径都被拒绝。战利品表设置不开放：用户包不能自带数据包，理由与替代见[文件结构](#文件结构)一节；静态补给可在模板箱子中预摆物品，每次 `load` 整份复制世界即天然刷新

修改权限边界：用户包只能修改自己借到的竞技场，以及自己有修改权的比赛——自己注册地图的比赛，或本场已启用自己 Lua 规则的比赛（启用即授予）。归属裁定在引擎侧统一进行（不暴露给脚本），越界即抛错。`arena.load` / `arena.clear_chest` 要求借入者是当前包；`match.widen` 只能登记本包的竞技场；`arena.teleport` 还要求目标玩家属于上述比赛（含已淘汰；地图 `on_start` 执行的启动阶段同样放行）。没有进行中的比赛时 `arena.teleport` 一律抛错——竞技场是自己借的也不等于能挪动无关玩家。事件回调只递值载荷，不暴露可修改的实体对象

## 加载与校验

Java 侧的校验收敛为三层，`/assets/` 里的文件没有第四层——插件不知道也不需要知道这些文件的格式，内容原样交给脚本解释，格式校验属于各包的 Lua

| 层           | 内容                                                     |
|--------------|----------------------------------------------------------|
| 包结构       | 目录/文件存在性、条目路径合法、大小上限                  |
| pack.varmeta | 引导字段，做固定闭集检查（未知字段拒绝、类型、取值语义） |
| 脚本 API     | Lua 调用注册/声明函数的传参检查，每个 API 入口自带契约   |

zip 与展开目录是同一包格式的两种载体，插件对二者的读取行为一致——开发时用目录，发布时打 zip。已加载的包内容视为只读

已知约束：

- 条目名是用户可控的，解析后的路径必须仍在包根内（zip-slip）
- 读取条目前检查声明大小，防 zip 炸弹
- 包内不支持嵌套压缩包；未来包内附带 resourcepack 时，内层压缩文件在外层包中须以 STORED（不压缩）方式存储（jar-in-jar 同款约束）
- `/resourcepack/` 的加载方式待定（解压交给原版，或由插件自行解析）。资源包后续可能将插件自身资源与所有用户包资源动态合并，经原版协议发给玩家
